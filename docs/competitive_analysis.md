# 竞品分析与 MSV 产品策略

## 1. 文档目的

本文分析三个与 Model Structure Viewer（MSV）相关的公开产品：

- [LLM Inference Analyzer](https://inference-analyzer.app/)
- [LLM Architecture Gallery](https://sebastianraschka.com/llm-architecture-gallery/)
- [modelmap](https://modelmap.cc/)

分析目标不是复刻竞品，而是回答：

1. 这些产品分别解决了什么用户问题？
2. 它们在模型入口、架构表达、成本分析和知识沉淀上采用了什么方法？
3. 哪些能力值得 MSV 吸收，哪些能力会导致 MSV 偏离既定定位？

本文以 2026-09-09 访问到的公开页面为观察依据。竞品页面和模型清单会持续变化，因此本文记录的是产品形态和交互模式，不把页面中的动态模型数量视为长期承诺。

## 2. MSV 的分析基线

MSV 当前定位是：读取模型配置、公开元数据和 safetensors header，生成可解释的结构、公式、显存、并行和瓶颈信息。

MSV 的五项核心能力见 [`principles.md`](principles.md)：

1. 零权重下载获取完整结构图。
2. 显存分解、逐卡 fit 和并行投影。
3. 使用 Transformers 做结构校验。
4. 解释算子、公式以及算力、带宽和通信瓶颈。
5. 保持轻量并支持静态部署。

竞品分析中的“学习”必须落到现有边界内。MSV 不因竞品存在就增加吞吐预测、调度仿真、最优并行方案搜索或真实 benchmark 闭环。

## 3. 竞品全景

| 产品 | 核心定位 | 主要用户 | 主要输出 | 交互特征 | 对 MSV 的参考价值 |
|---|---|---|---|---|---|
| LLM Inference Analyzer | 模型架构目录与推理成本分析 | 推理工程师、算力规划人员 | 模型列表、结构原语、显存/并行/Roofline 报告 | 搜索、模型卡片、原语 tooltip、报告入口、架构演进 | 高：目录、原语、成本报告、覆盖反馈 |
| LLM Architecture Gallery | LLM 架构知识库与图示画廊 | 研究者、开发者、学习者 | 架构图、事实说明、模型/文章链接 | 搜索、模型卡片、图示、事实描述、文章跳转 | 高：事实卡片、横向比较、知识沉淀 |
| modelmap | 任意 Hugging Face 模型的动画架构地图和 GPU fit 检查 | 模型使用者、部署工程师、学习者 | 动态架构地图、参数/显存摘要、GPU 可放置性 | 输入模型、动画展开、交互地图、硬件 fit | 高：首次使用体验、动态解释、快速 fit 判断 |
| MSV | 可验证的模型结构与理论成本解释器 | 模型工程师、推理工程师、适配开发者 | Graph IR、结构图、公式、证据、成本和并行分析 | 来源选择、图联动、Cost Lens、Inspector、导出 | 核心差异：证据链和算子级解释能力更强 |

### 3.1 竞争关系

三个竞品覆盖了不同的用户任务：

```text
Gallery              -> 我想理解和比较模型架构
modelmap             -> 我想快速看懂一个 HF 模型，并判断 GPU 是否放得下
Inference Analyzer   -> 我想估算推理时的显存、并行和硬件瓶颈
MSV                  -> 我想知道结构是否可信，以及结构如何推导出成本和瓶颈
```

MSV 不需要在每一个入口体验上都超过竞品。更合理的策略是吸收 Gallery 的知识组织、modelmap 的即时反馈和 Inference Analyzer 的成本视角，再用 Graph IR、Transformers evidence 和 safetensors header 建立工程可信度。

## 4. 单项竞品分析

### 4.1 LLM Inference Analyzer

### 产品形态

首页采用模型目录形式，模型卡片展示模型 ID、结构原语、访问量、支持状态和添加入口。页面支持中英文切换、模型搜索、未覆盖架构展示以及架构演进入口。

模型被抽象成一组可检索的结构原语，例如：

- GQA
- MLA
- MoE FFN
- GDN
- Gated Attention
- DSA
- Vision tower
- Compressed Attention

原语带有解释 tooltip，用户可以直接从模型列表理解“这个模型用了什么结构”。

### 主要优点

1. **模型入口明确**：用户先从已有模型目录开始，不需要理解输入格式。
2. **结构原语可比较**：模型名称之外增加了稳定的结构标签。
3. **成本分析与结构关联**：显存、并行切分和 Roofline 分析围绕结构原语展开。
4. **覆盖缺口可见**：未覆盖架构能够被展示，并允许用户请求支持。
5. **架构演进独立成入口**：模型结构变化不只是单模型详情里的附属信息。

### 局限与 MSV 的判断

其价值依赖模型适配和公式维护。原语标签如果没有配置来源、公式来源和验证状态，容易变成“人工标注的结论”。MSV 应借鉴原语视角，但必须给每个结论保留证据等级和来源。

### MSV 应吸收

- 首页模型 Catalog。
- `primitives[]` 作为模型的产品级索引。
- 支持、部分支持、未覆盖三态展示。
- 原语知识卡：定义、结构影响、成本影响、支持模型。
- 架构演进和模型族谱入口。
- 未覆盖模型的可追踪反馈记录。

### MSV 不应照搬

- 不把理论 Roofline 结果描述成真实吞吐。
- 不把“能生成图”等同于“已验证支持”。
- 不为了追求目录数量，绕过结构真值和公式注册约束。

### 4.2 LLM Architecture Gallery

### 产品形态

Gallery 以模型架构图和事实说明为核心。页面通过模型卡片、搜索和统一格式的模型描述，把不同年代、不同厂商和不同规模的模型放在同一知识空间中。

每个模型通常有：

- 架构图。
- 模型规模和层数等结构事实。
- Attention、FFN、MoE、上下文等关键信息。
- 一段解释该模型相对其他模型变化的文字。
- 返回原始文章或对应章节的链接。

### 主要优点

1. **低门槛理解**：先看图，再看简短事实和解释。
2. **统一事实格式**：模型之间容易进行横向比较。
3. **知识沉淀能力强**：模型图不是孤立页面，而是文章、模型族和演进历史的一部分。
4. **人工解释补足配置字段**：用户能够理解“为什么这个结构重要”。
5. **适合建立共同语言**：原语名称、模型名和结构变化之间有稳定关联。

### 局限与 MSV 的判断

Gallery 主要是编辑维护的知识库，实时性、自动验证和权重级精度不是核心目标。它适合解释“已知模型”，不直接解决用户自定义模型、配置异常或显存 fit 问题。

### MSV 应吸收

- 统一的 Architecture Fact Sheet。
- 模型之间的结构 diff。
- 模型族谱和架构演进时间线。
- 每个结构结论都附“为什么重要”的解释。
- 关联模型卡、论文、官方文档和源码位置。

### MSV 不应照搬

- 不以静态图片作为唯一结构事实。
- 不把人工文章内容替代 Graph IR。
- 不牺牲自定义配置和本地模型能力来追求固定模型画廊。

### 4.3 modelmap

### 产品形态

modelmap 的公开定位是“Interactive, animated architecture maps for any Hugging Face model — and whether it fits on your GPU”。它强调两个即时结果：

1. 模型结构以可交互、可动画的地图展开。
2. 根据模型规模和硬件条件快速判断是否能放入 GPU。

这类产品通常把复杂结构压缩为一条更适合浏览的架构路径，让用户从 Embedding、Attention、FFN、Norm、LM Head 等高层模块逐步展开，而不是一次显示全部实现细节。

### 主要优点

1. **首次反馈快**：输入模型后尽快得到可视化结果。
2. **动画强化结构顺序**：适合建立从输入到输出的执行直觉。
3. **地图化表达易于浏览**：比完整拓扑图更适合非专家快速阅读。
4. **GPU fit 是明确任务**：用户能快速回答“这张卡放不放得下”。
5. **面向任意 HF 模型**：用户心智模型简单，入口不需要先选择模型来源。

### 局限与 MSV 的判断

高层地图适合入门和快速判断，但会隐藏残差、跨层级连接、共享参数、MoE 路由、dtype 和并行切分等细节。动画也不应被误读为真实运行时 trace。

MSV 可以借鉴其“渐进展开”和“快速 fit”体验，但必须保留：

- 节点事实和显式边。
- `declared` 与推断边的证据区别。
- 父节点聚合、叶子公式和参数归属。
- dtype、权重来源、并行策略和不确定性。

### MSV 应吸收

- 默认提供高层结构摘要视图。
- 支持由模型级到 block、layer、operator 的渐进展开。
- 首屏给出逐卡显存 fit 结论。
- 用轻量动画表达结构展开、路径聚焦和计算阶段切换。
- 让“看懂结构”和“判断放置”成为同一条工作流。

### MSV 不应照搬

- 不做模拟真实推理执行的动画。
- 不把 GPU fit 简化成只比较总参数量和显存。
- 不隐藏证据等级以换取更顺滑的视觉效果。

## 6. 对 MSV 的产品结论

### 6.1 目标用户分层

MSV 应服务三个相互关联但需求不同的用户：

| 用户 | 首要问题 | 需要的默认视图 |
|---|---|---|
| 学习者/研究者 | 这个模型的结构是什么，和其他模型有什么区别 | 高层结构图、Fact Sheet、原语解释 |
| 模型适配开发者 | config 和真实 Transformers 结构是否一致 | Graph、验证结果、诊断、源码/字段证据 |
| 推理工程师 | 需要多少显存，TP/EP/PP 后瓶颈在哪里 | Cost Lens、逐卡 fit、并行和通信投影 |

一个页面可以覆盖三类用户，但首屏必须先回答模型是谁、结构由什么组成、结论可信度如何。

### 6.2 推荐的信息架构

```text
Model Catalog
  -> Model Profile
       -> Overview
       -> Architecture Map
       -> Layers / Operators
       -> Memory & Fit
       -> Parallelism
       -> Evidence & Diagnostics
       -> Compare
       -> Export
```

其中：

- `Model Catalog` 借鉴 Inference Analyzer 的目录入口。
- `Model Profile` 借鉴 Gallery 的统一事实卡。
- `Architecture Map` 借鉴 modelmap 的渐进展开。
- `Memory & Fit` 和 `Parallelism` 延续 MSV 的现有 Cost Lens。
- `Evidence & Diagnostics` 是 MSV 的核心差异化。

### 6.3 推荐的 Model Profile

建议在 Graph IR 之上增加面向目录、摘要和比较的产品层对象。建议字段如下：

```text
ModelProfile
├── identity
├── family
├── release
├── architecture
├── primitives[]
├── dimensions
├── parameter_summary
├── memory_summary
├── parallelism_summary
├── evidence[]
├── coverage_status
└── related_models[]
```

`Graph IR` 继续作为结构事实源；`ModelProfile` 只负责产品展示、检索、比较和演进，不复制另一套结构真值。

## 7. 对现有能力的具体借鉴

### P0：Catalog 和 Fact Sheet

目标：让用户能够快速找到模型并理解模型。

- 将现有 `models/catalog.json` 做成首页模型目录。
- 增加厂商、系列、参数规模、Dense/MoE、Attention、模态和支持状态筛选。
- 在模型详情首屏展示固定格式 Fact Sheet。
- 展示字段来源、验证状态和未知字段，不用默认值掩盖缺失信息。
- 搜索同时匹配模型 ID、架构名和结构原语。

验收重点：

- 新用户不输入模型 ID 也能进入一个已支持模型。
- 10 秒内可以看到模型规模、层数、Attention、FFN/MoE、上下文和 fit 结论。
- Fact Sheet 与 Graph、公式和导出结果共享同一模型事实。

### P1：原语知识层和模型对比

目标：把单模型查看升级为结构理解和差异定位。

- 为每个原语增加定义、作用、成本影响和支持模型。
- 支持两个模型的结构节点 diff。
- 差异至少覆盖层数、hidden size、Attention、KV Cache、MoE、视觉模块和并行相关字段。
- 对“结构不同但参数相近”和“参数不同但结构相同”分别提供解释。

验收重点：

- 用户可以回答两个模型为什么显存不同。
- 对比结果能回链到 Graph 节点、公式和证据。

### P2：架构演进和模型族谱

目标：形成可持续的架构知识资产。

- 为模型建立 family、parent、variant 和 release metadata。
- 根据原语和结构 diff 生成演进节点。
- 支持从模型进入同族模型、相邻架构和相关原语。
- 允许导出适合文档和评审的演进报告。

验收重点：

- 演进节点能回到具体模型和结构证据。
- 时间线不会把推测关系展示成确定事实。

### P2：结构解释动画

目标：吸收 modelmap 的易用性，但不模拟运行时。

- 展开模型级、block 级、layer 级和 operator 级视图。
- 用短时过渡动画表达展开、聚焦和路径定位。
- 明确标识“结构导航动画”，不宣称是运行时 trace。

验收重点：

- 动画不改变 Graph 事实、不隐藏边证据、不影响键盘和移动端使用。
- 关闭动画后信息完整可用。

## 8. 明确不纳入 MSV 的能力

以下能力即使竞品或其他工具提供，也不纳入当前 MSV 范围：

- 自动搜索并推荐最优 TP/PP/EP/DP 方案。
- 吞吐、延迟、TTFT 或线上性能预测。
- 真实推理 trace、调度和批处理仿真。
- 训练内存规划，包括优化器状态、梯度和激活重算。
- 以实测 benchmark 校准理论公式并形成性能承诺。
- 用动画伪造 kernel 执行或通信 overlap。

这些边界与 [`principles.md`](principles.md) 和 [`implementation_plan.md`](implementation_plan.md) 一致。

## 9. 差异化策略

MSV 的差异化不应是“模型数量最多”或“动画最复杂”，而应集中在四点：

### 9.1 可信结构

同一个模型同时保留：

- config 来源。
- safetensors header 来源。
- Transformers 验证结果。
- Graph builder 和 registry 版本。
- 节点、边和公式的证据等级。

### 9.2 结构到成本的可解释链路

用户从一个成本结论可以回到：

```text
成本结论
  -> 聚合成本
  -> 叶子算子
  -> 公式与 counts
  -> shape / dtype / phase
  -> config 或权重 header
```

### 9.3 面向工程决策

MSV 不只回答“结构是什么”，还回答：

- 哪些参数实际被激活？
- KV Cache 为什么占这些显存？
- 哪个节点受算力、带宽或通信限制？
- 换芯片或并行策略后，瓶颈是否变化？
- 当前结论是事实、推导还是假设？

### 9.4 轻量和可部署

保持前端静态部署、零权重下载、前端不安装 torch，是 MSV 相比重型分析平台的重要工程优势。

## 10. 路线图与优先级

| 阶段 | 目标 | 主要产出 | 依赖 |
|---|---|---|---|
| P0 | 入口产品化 | Catalog、筛选、Fact Sheet、覆盖状态 | 现有 catalog、summary、diagnostics |
| P1 | 建立比较能力 | 原语知识层、模型对比、结构 diff | Graph IR、stable node id |
| P1 | 强化成本决策 | 首屏 fit 结论、成本证据链、报告化展示 | Cost Lens、公式和 header |
| P2 | 知识资产化 | 架构演进、模型族谱、相关模型 | release metadata、family 关系 |
| P2 | 降低学习门槛 | 渐进展开、结构解释动画 | diagram 交互和无障碍验收 |

每一阶段必须满足：

- 不引入第二套结构事实。
- 不把未知值当作零。
- 不把理论分析描述成实测性能。
- 有对应的模型、Graph、成本和页面测试。

## 11. 建议指标

指标用于验证产品方向，不用于制造虚假的性能承诺。

### 使用效率

- 从首页进入已支持模型详情的步骤数。
- 首次看到 Fact Sheet 和 fit 结论的时间。
- 从成本结论回到对应结构节点的操作步数。
- 模型对比任务的完成率。

### 覆盖和可信度

- 已覆盖模型数。
- 已验证模型占已覆盖模型的比例。
- 未覆盖架构被发现和反馈的数量。
- 结构结论带证据来源的比例。
- 前后端 Graph parity 测试通过率。

### 工程价值

- 用户导出报告的数量。
- 成本分析中被定位到具体算子或结构原语的比例。
- 不同芯片/并行方案比较任务的完成率。
- 因诊断信息发现并修复模型适配问题的数量。

## 12. 结论

三个竞品分别提供了三种值得吸收的产品模式：

```text
Inference Analyzer -> 目录、结构原语、成本报告、覆盖反馈
Architecture Gallery -> 事实卡、横向比较、知识库和架构演进
modelmap -> 快速反馈、渐进展开、地图化表达、GPU fit
```

MSV 的推荐方向是：

```text
可检索的 Model Catalog
  + 统一的 Architecture Fact Sheet
  + 可展开且可验证的 Graph
  + 原语级知识和模型对比
  + 显存/并行/瓶颈 Cost Lens
  + 可追溯的 Evidence
```

最终产品心智应从“查看模型结构”升级为：

> 可信地解释一个模型是什么、为什么是这样，以及它在给定芯片和并行方案下会产生什么理论成本。
